DHCP

Dynamic Host Configuration Protocol – automated assignment of IP addresses and network configuration to devices

Overview

DHCP (Dynamic Host Configuration Protocol) is the network service that automatically hands out IP addresses and related configuration — subnet mask, default gateway, DNS servers, and more — to devices as they join a network. Without it, every device would need to be configured manually, which is impractical at any meaningful scale. Defined in RFC 2131, DHCP operates over UDP using port 67 (server) and port 68 (client), and it is one of the quiet foundations that almost every other network service depends on.

How DHCP Works: The DORA Process

A client obtains an address through a four-step exchange, commonly remembered by the acronym DORA:

  • Discover – The client broadcasts a DHCPDISCOVER to find any available DHCP server.
  • Offer – One or more servers reply with a DHCPOFFER proposing an address and configuration.
  • Request – The client broadcasts a DHCPREQUEST accepting one specific offer.
  • Acknowledge – The chosen server confirms with a DHCPACK, committing the lease.

Addresses are issued as time-limited leases. The client attempts to renew at roughly 50% of the lease duration (the T1 timer) and, if that fails, tries to rebind from any server at about 87.5% (the T2 timer) before the lease expires.

Core Components

  • Scope – The pool of addresses a server can lease for a given subnet, with associated settings.
  • Reservation – A fixed address tied to a device's MAC address, so it always receives the same IP while still being managed centrally.
  • Exclusion – Addresses inside a scope that are held back (e.g. for statically configured servers).
  • Lease – The time-bound assignment of an address to a client.
  • Options – Additional configuration delivered alongside the address, such as default gateway (option 003), DNS servers (006), domain name (015), and PXE/boot settings (066/067) for network imaging.

DHCP Relay

Because DHCPDISCOVER is a broadcast and routers do not forward broadcasts between subnets, a DHCP relay agent (often configured as an ip helper-address on a router or switch) intercepts client requests and forwards them as unicast to a central DHCP server. This lets a small number of centralized servers handle addressing for many subnets, rather than placing a server on every segment.

High Availability & Redundancy

DHCP is a critical-path service: if it fails, new and renewing devices lose connectivity. Common resilience approaches:

Approach How it works Trade-off
Failover (load-balance) Two servers share a scope and split active leases Best balance of capacity and resilience
Failover (hot standby) One server is active, the other takes over on failure Simpler, but standby capacity sits idle
Split scope (80/20) Two servers hold non-overlapping parts of one range Works without failover support but wastes addresses

Security Considerations

  • Rogue DHCP servers – An unauthorised server (accidental or malicious) can hand out bad gateways and DNS, enabling interception. Mitigate with DHCP snooping on switches, which trusts only designated ports.
  • DHCP starvation – An attacker floods requests with spoofed MAC addresses to exhaust the pool. Mitigate with port security and rate limiting.
  • Option 82 – Relay agent information that helps servers make policy decisions and adds an audit trail.
  • Logging & auditing – Lease logs map addresses to devices over time, which is valuable for incident response and compliance.

DHCPv6 & Cloud

For IPv6, DHCPv6 (ports 546/547) works alongside or instead of Stateless Address Autoconfiguration (SLAAC), using multicast rather than broadcast. In public cloud, you typically don't run DHCP servers yourself — providers manage addressing within a VPC/VNet, and you influence behaviour through constructs such as AWS DHCP option sets (for example, custom DNS and domain names).

IT Director Considerations

  • Centralised vs distributed DHCP architecture and its impact on resilience and WAN dependency
  • Integration with DNS and Active Directory, including Dynamic DNS (DDNS) record updates
  • IP Address Management (IPAM) tooling for visibility across scopes, sites and cloud
  • Redundancy design aligned to availability SLAs for a service with no graceful failure mode
  • Security hardening (snooping, rogue-server detection) as part of network access control
  • Lease and audit logging to support security investigations and compliance evidence

DHCP vs Static Addressing

Use DHCP for the vast majority of endpoints — laptops, phones, printers and general workstations — where centralised, automated management is essential. Use static addressing or reservations for infrastructure that must be predictable, such as servers, network gear, and devices referenced by IP in firewall rules or applications. Reservations are usually preferable to pure static configuration because they keep that predictability while remaining centrally managed.
