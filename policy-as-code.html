Policy as Code (OPA/Kyverno)

Defining and enforcing governance rules as version-controlled, automatically enforced code

Overview

Policy as Code defines governance, compliance, and security rules as version-controlled code rather than manually enforced documentation, using tools like Open Policy Agent (OPA) or Kyverno to automatically evaluate and enforce policies at deployment time — most commonly as Kubernetes admission controllers blocking non-compliant resources before they're created. In 2026, policy as code has expanded beyond Kubernetes into broader infrastructure-as-code validation, CI/CD pipeline gates, and cloud resource governance, treating policy the same way modern teams treat application code.

Key Value: Policy as code turns governance from a manually reviewed checklist into an automatically enforced gate — the same shift DevOps brought to infrastructure provisioning — catching non-compliant resources at creation time rather than during a periodic audit that finds violations long after they've been running in production.

Core Components

Policy Engines

  • Open Policy Agent (OPA) — general-purpose policy engine (Rego language)
  • Kyverno — Kubernetes-native policy engine (YAML-based)
  • Cloud-native policy services (AWS Config Rules, Azure Policy)

Enforcement Points

  • Kubernetes admission control (blocking non-compliant resources)
  • CI/CD pipeline gates (Terraform/IaC validation)
  • Runtime policy evaluation for ongoing compliance checking

Governance Application

  • Security baseline enforcement (no privileged containers, required labels)
  • Cost & resource governance (quota, tagging enforcement)
  • Compliance mapping to regulatory & internal standards

Best Practices

  • Start with policies in audit/warn mode before moving to hard enforcement
  • Version-control policies with the same rigor as application code
  • Apply policy enforcement at multiple points — CI/CD gates and runtime admission control both
  • Map policies explicitly to specific compliance or security requirements for traceability
  • Involve application teams in policy design to avoid overly restrictive, workflow-breaking rules

IT Director Responsibilities

  • Sponsor policy-as-code adoption for security & compliance enforcement
  • Ensure policies are versioned, tested & rolled out gradually (audit before enforce)
  • Map enforced policies to specific compliance & security requirements
  • Balance enforcement rigor against application team workflow impact
