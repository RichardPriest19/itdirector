OSPF

Open Shortest Path First – the vendor-neutral link-state protocol for routing inside a network

Overview

OSPF (Open Shortest Path First) is an Interior Gateway Protocol — it routes traffic within a single organisation's network rather than between separate organisations. It is an open standard (RFC 2328 for OSPFv2/IPv4, RFC 5340 for OSPFv3/IPv6), which is part of why it is so widely deployed across mixed-vendor estates. OSPF is a link-state protocol: every router builds a complete map of the network and independently calculates the best paths, giving fast, loop-free convergence. It runs directly over IP as protocol number 89.

How It Works

Each router floods Link State Advertisements (LSAs) describing its connections. All routers in an area assemble these into an identical link-state database (LSDB), then run Dijkstra's Shortest Path First algorithm to compute the lowest-cost route to every destination, where cost is derived from link bandwidth. Routers discover and maintain relationships through Hello packets, forming adjacencies. On shared multi-access segments, a Designated Router (DR) and Backup DR are elected to limit the number of adjacencies and reduce flooding.

Areas & Hierarchy

OSPF scales through a two-level hierarchy of areas, which confines flooding and SPF recalculation to smaller domains:

Concept Role
Backbone (Area 0) Central area all other areas must connect to
Area Border Router (ABR) Connects an area to the backbone and summarises routes
ASBR Injects external routes (e.g. from BGP) into OSPF
Stub / NSSA areas Reduce LSA volume by blocking external routes

OSPF vs Other Interior Protocols

  • EIGRP — fast and simple to operate, but historically Cisco-centric; OSPF's open standard makes it the safer choice in multi-vendor networks.
  • IS-IS — another link-state protocol with similar properties, favoured by some large service providers; OSPF is more common in enterprise and campus networks.
  • RIP — an older distance-vector protocol that does not scale and is effectively legacy.

Security Considerations

  • Neighbour authentication — OSPF supports authenticated adjacencies (MD5/SHA) so rogue devices cannot inject routes.
  • Passive interfaces — disable OSPF on interfaces facing endpoints or untrusted segments to reduce exposure.
  • Route filtering and summarisation — limit what is advertised between areas to contain mistakes and tighten the blast radius.

IT Director Considerations

  • Choice of IGP across the estate, weighing vendor neutrality (OSPF) against operational familiarity (e.g. EIGRP)
  • Hierarchical area design as a prerequisite for scaling campus, branch and data-centre networks
  • Convergence behaviour and its impact on availability SLAs during link or device failure
  • Redistribution between OSPF and edge protocols such as BGP, and the risk that introduces
  • Documentation and skills, since link-state design is less forgiving of ad-hoc growth

OSPF vs BGP

Use OSPF inside a network you control end to end, where the goal is fast, automatic convergence on the shortest path. Use BGP at the boundaries — connecting to ISPs, other organisations, or across very large fabrics — where routing policy and scale outweigh convergence speed. Most real-world networks run both: OSPF as the interior fabric and BGP at the edge, with controlled redistribution between them.
