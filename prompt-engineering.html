Prompt Engineering

Crafting the inputs to an LLM to get more accurate, reliable and useful outputs

Overview

Prompt engineering is the practice of designing the instructions and context given to a large language model in order to get better results. Because an LLM's output depends heavily on how it is asked, the wording, structure and examples in a prompt can be the difference between a vague, unreliable response and a precise, useful one. It is the cheapest and fastest way to influence a model's behaviour — no training, no infrastructure, just a better-constructed input — which is why it is usually the first lever to reach for.

Common Techniques

  • Clear, specific instructions — say exactly what you want, including constraints and the desired format.
  • Few-shot examples — show the model one or more examples of the input/output you expect.
  • Chain-of-thought — ask the model to reason step by step for problems that need working through.
  • Role / system prompts — set a persona or standing rules that frame the whole interaction.
  • Output formatting — specify structure (e.g. a list, table or JSON) so results are easy to use downstream.
  • Providing context — supply relevant background directly in the prompt.

Strengths & Limits

Strengths Limits
No training, cost or infrastructure Cannot add knowledge beyond the prompt/context
Immediate to apply and iterate Can be brittle and sensitive to wording
Accessible to non-specialists Behaviour varies between models

IT Director Considerations

  • A practical, low-cost skill worth building across teams, not just in technical roles
  • Treating effective prompts as reusable assets — managed, versioned and shared
  • Prompt management and testing as part of an LLMOps / MLOps practice
  • Security awareness, including prompt injection where untrusted input reaches a model
  • It is the first lever to try before investing in RAG or fine-tuning
  • Consistency, since the same prompt can behave differently across models and versions

Prompt Engineering, RAG & Fine-Tuning

Prompt engineering is the lightest of the three ways to adapt an LLM. Prompt engineering shapes the input and costs almost nothing — the right starting point for most needs. RAG goes further by automatically retrieving and inserting relevant knowledge into the prompt, addressing what the model doesn't know. Fine-tuning goes further still by retraining the model to change how it behaves. They build on each other — and RAG itself is, in part, automated prompt construction with retrieved context.
