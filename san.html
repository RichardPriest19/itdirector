SAN

Storage Area Network – high-performance block storage delivered to servers over a dedicated network

Overview

A SAN (Storage Area Network) is a dedicated, high-speed network that presents centralised storage to servers as if it were locally attached disk. Crucially, a SAN delivers block-level storage: servers see raw volumes (LUNs) that they format and manage with their own file systems, exactly as they would a physical drive. This makes SANs the traditional choice for demanding, performance-sensitive workloads such as databases, virtualisation clusters and transactional applications.

How It Works

Storage capacity on shared arrays is carved into logical units called LUNs, which are presented to servers across the storage network. The server's operating system treats a LUN as a local block device. Access is controlled through zoning (on the switch fabric) and LUN masking (on the array), which together ensure each server sees only the volumes it is entitled to. Because servers boot and run production workloads directly from these volumes, the SAN is engineered for low latency, high throughput and redundancy at every layer.

Common Protocols

Protocol Characteristics
Fibre Channel (FC) Dedicated, very high performance; needs separate HBAs and switches
iSCSI Block storage over standard Ethernet/IP; lower cost, easier to adopt
FCoE Fibre Channel encapsulated over Ethernet to converge networks
NVMe-oF NVMe over fabrics for very low-latency flash storage

Why Use a SAN

  • Performance — low latency and high throughput for databases and virtualisation.
  • Shared storage for clusters — multiple hosts accessing the same volumes underpins features like VM live migration and high availability.
  • Centralised management — snapshots, replication, thin provisioning and tiering handled on the array.
  • Boot from SAN — servers can be stateless, simplifying recovery and refresh.

IT Director Considerations

  • Higher cost and specialist skills, particularly for Fibre Channel fabrics
  • iSCSI as a lower-cost entry point using existing Ethernet infrastructure
  • Redundancy design — multipathing, dual fabrics and array resilience to avoid single points of failure
  • Replication and snapshots as part of backup and disaster-recovery strategy
  • How hyper-converged infrastructure (HCI) and cloud block storage may reduce or replace a traditional SAN
  • Capacity planning and the operational overhead of a dedicated storage tier

SAN vs NAS

The defining difference is the level at which storage is shared. A SAN provides block-level storage — raw volumes a server formats and treats as its own disk — over a dedicated, high-performance network, making it ideal for databases and virtualisation. A NAS provides file-level storage — shared folders accessed over the existing network — making it ideal for user data and collaboration. In short: SAN for performance-critical block workloads, NAS for shared files. Many organisations run both, and modern unified arrays can serve each.
