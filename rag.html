RAG

Retrieval-Augmented Generation – grounding LLM answers in your own, current data

Overview

Retrieval-Augmented Generation (RAG) is a technique for making a large language model answer from your data rather than only from what it learned during training. Instead of relying on the model's frozen, general knowledge, RAG retrieves relevant information from a knowledge base at query time and supplies it to the model as context. This grounds the answer in current, specific, often private information — dramatically reducing hallucination and letting the model cite its sources. RAG has become the dominant pattern for enterprise AI applications such as "chat with our documents".

How It Works

RAG has two phases. Ingestion happens ahead of time: documents are split into chunks, converted into embeddings, and stored in a vector database. Retrieval and generation happen at query time:

  • The user's question is embedded and used to search the vector database for the most relevant chunks.
  • Those chunks are inserted into the prompt as context.
  • The LLM generates an answer grounded in that retrieved content, ideally with citations.

In effect, RAG turns the open-book exam: the model answers with the right reference material in front of it.

Why It Matters

  • Current & private knowledge — answer from data the model was never trained on.
  • Reduced hallucination — grounding answers in real source material improves accuracy.
  • Traceability — citations let users verify where an answer came from.
  • No retraining — update the knowledge base instead of retraining the model.
  • Cost-effective freshness — keeping content current is far cheaper than fine-tuning.

RAG vs Fine-Tuning

These are often posed as alternatives, but they solve different problems. RAG adds knowledge — giving the model access to information it doesn't hold. Fine-tuning changes behaviour — teaching the model a style, format or specialised task. If the issue is "the model doesn't know our facts", RAG is usually the answer; if it's "the model doesn't respond in the way we need", fine-tuning may be. Many sophisticated systems use both.

IT Director Considerations

  • Data freshness — a process to keep the knowledge base current as content changes
  • Security and permissions, so RAG never surfaces documents a user shouldn't see
  • Retrieval quality, since poor chunks lead to poor answers ("garbage in, garbage out")
  • Evaluation — measuring grounding and accuracy, not just fluency
  • Cost of embedding and storing large document estates
  • It is usually the first thing to try for knowledge-based use cases, ahead of fine-tuning

RAG in the AI Stack

RAG is the application pattern that ties the other pieces together. It depends on embeddings to represent meaning, a vector database to retrieve relevant content quickly, and an LLM to generate the final answer. Alongside prompt engineering and fine-tuning, it is one of the three main ways to adapt an LLM — the one focused on supplying knowledge.
